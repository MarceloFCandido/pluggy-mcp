# Review decisions

This records the follow-up to the independent Claude review of `09e8b28` and the human comments on PR #1. The numbered rows match Claude's ten findings. Findings were checked against the code, with regression cases for the changed behavior; several new cases failed against the original implementation before the fixes.

| Finding                                                           | Validation and change                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ----------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. Webhook headers can expose the receiver secret                 | Valid: API bodies passed directly to MCP results. Webhook administration has been removed from the catalog and dispatch along with other application administration. Protocol tests reject those calls before an API request. Configure delivery headers outside the conversation.                                                                                                                                                                 |
| 2. Missing transactions remain active after polling               | Valid for pending entries. Full transaction imports now retire absent pending records, including when the returned set is empty; incremental batches do not. Posted and investment history stays retained. We did **not** adopt deletion based on the earliest returned date: that date does not establish a complete coverage window, and deleting on that inference could lose history. Confirmed posted deletions still require webhook events. |
| 3. Removed accounts and withdrawn products retain usable scopes   | Valid. Queries only include currently returned accounts and disclose removed IDs in `excludedAccountIds`; direct reads of their collections fail. Missing account/investment parents and withdrawn products invalidate their dependent scopes. A failed parent refresh also reports its error on retained children.                                                                                                                                |
| 4. Event retries exhaust quickly and ordinary reads hide failures | Valid. The queue persists `next_attempt_at`; retries start at 30 seconds and double, with ten attempts. Read freshness includes pending/failed counts and `EVENT_PENDING`/`EVENT_FAILED`. Due events are processed by the worker and by an explicit sync; manual retries reset the schedule under the application lock.                                                                                                                            |
| 5. The item registry grows implicitly                             | Valid. `PLUGGY_ITEM_IDS` is now the sole allowlist. Startup disables removed IDs without erasing retained rows. Unknown-item events are ignored, explicit sync cannot add IDs, and the registration tool has been removed. All processes sharing a mirror must use the same configuration.                                                                                                                                                         |
| 6. Bank and card signs can cancel in default totals               | Valid; Pluggy documents positive card charges and negative bank debits. Summaries now always separate both account and currency, and describe the raw sign convention. Tests cover bank -100 and card +60 producing separate groups.                                                                                                                                                                                                               |
| 7. Item health defaults to a cached response                      | Valid. `items-retrieve` always uses the API; tests return current login-error status despite an older healthy mirror record. Cached account balances remain explicitly dated snapshots.                                                                                                                                                                                                                                                            |
| 8. Hidden auth can invalidate the mirror                          | Valid: lookup previously resolved an operation omitted from discovery. Auth is now absent from tool dispatch. A valid direct call returns `UNKNOWN_TOOL` without changing scope readiness.                                                                                                                                                                                                                                                         |
| 9. Stdio clients compete for the webhook port                     | Valid. Timers and the receiver now run only in `worker` mode. The subprocess test runs a worker and a stdio client with the same configuration. A second worker reports `WEBHOOK_LISTEN_FAILED` rather than a credential error.                                                                                                                                                                                                                    |
| 10. Query offsets drift between imports                           | Valid. The structured query uses revision-bound cursors, shared with the existing cursor validation. Each database read uses a repeatable-read transaction for coherent rows and metadata. An intervening change rejects the next cursor rather than silently duplicating rows.                                                                                                                                                                    |

## Other observations

- Database date bounds are inclusive UTC dates and ordering is date/ID ascending. The API retains its own ordering. These source differences are documented rather than claiming interchangeable page numbers; [Pluggy's cursor reference](https://docs.pluggy.ai/en/reference/transaction/transactions-list-by-cursor) confirms inclusive date filters, and its [transaction guide](https://docs.pluggy.ai/en/docs/products/transactions) describes UTC dates and card signs.
- Connection health is live. Cached account balances are described as snapshots; current balances require an API read.
- A direct PostgreSQL connection is the supported default. Session poolers need compatible startup parameters and advisory locks; transaction pooling is unsupported. The unnecessary startup timezone option was removed because date calculations already specify UTC.
- Only HTTP 404 with `IDENTITY_NOT_FOUND` becomes an empty identity collection. Other errors remain failures.
- Only writes that can affect mirrored data invalidate it. An unsuccessful such write remains conservatively invalidated, because the remote outcome can be uncertain. Unrelated connection settings leave the mirror valid.
- Unsupported OpenAPI parameter locations now fail catalog construction instead of being silently omitted. The upstream snapshot stays unmodified; the household endpoint selection is explicit.

## Complexity choices

The redundant per-collection advisory lock was removed; the application lock already coordinates runtime imports, events, configuration changes, and mirrored writes. The API-only registration tool was removed as part of using one configured item list.

Targeted transaction events are retained because [Pluggy recommends filtered created/updated/deleted events](https://docs.pluggy.ai/en/reference/transaction/transactions-list-by-cursor). They avoid a whole-history fetch for each correction. Item events still import the other products. Creation events without a usable timestamp re-read the account; payload URLs are ignored entirely. There is one HTTP client, no ORM, no arbitrary SQL tool, and no filesystem financial cache.

## Human review comments

The README now includes complete API-only and PostgreSQL MCP configurations, and explains the conversation, one-time sync, standalone worker, and webhook workflows. JSONB is identified as `pluggy_mcp.records.data` inside PostgreSQL, with no third data store. Payment initiation, boleto issuing, credit-risk analysis, connect-token generation, credential validation, and webhook administration are outside the exposed catalog. The remaining financial and connection tools are listed in [API coverage](API.md).

Tests use mock Pluggy responses and disposable PostgreSQL. Live-account entitlements, real bank history coverage, and a production reverse proxy have not been validated.
